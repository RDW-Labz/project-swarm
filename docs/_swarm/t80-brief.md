# T80 brief — lesson tool for project-swarm 1.41.0 (decision #340)

Problem (measured 2026-10-01): coordination/swarm-lessons.md is 215 KB, 322 rows, 48 queued; rows run 500–1000 characters; nobody reads it at boot. The public copy skills/project-swarm/references/lessons.md (150 KB) and docs/lessons.md (155 KB) have no index. Only two paths carry a rule into a worker prompt today: `.swarm/gotchas.md` (tools/gotchas.mjs) and the worker skills (tools/skills.mjs, coordination/skills/<name>/SKILL.md with paths:/checks: frontmatter, <800 tokens). Hand-written rows have leaked company names (field lesson 293). Batch releases carry 5–20 lessons each and take a whole session plus a worker tier the project often lacks.

Build, in this order of payoff:
1. `swarm lesson add --area <worker-skill|gotchas|tool> --evidence <run id or log path> --rule "<one sentence>" --fix "<enforcement spec, one or two sentences>" [--public "<scrubbed line>"]` → one JSON line appended to `coordination/swarm-lessons.jsonl` under --root (`--file PATH` overrides): {id, date, area, evidence, rule, fix, public, status:"queued", test:null, version:null}. id = 1 + max(id in the jsonl, last id in the legacy markdown table `coordination/swarm-lessons.md` if present). Date from the clock, never from arguments. Every field passes the existing private-names check (the same mechanism `validate/integrate --private-names FILE` and the config private names use); refuse {"status":"error","code":"private-name","field":…} without ever printing the term.
2. Same-session routing: when --area names an existing worker skill (coordination/skills/<area>/SKILL.md), append `- <rule> (lesson <id>)` under a `## Lessons` heading (create it at the end if absent); refuse {"code":"skill-too-long","tokens":N,"cap":800} when the result would exceed the cap (token estimate = bytes/4, same as elsewhere in the tool) and write nothing. --area gotchas appends the same bullet to `.swarm/gotchas.md`. --area tool routes nowhere (the fix is a tool change). `lesson list [--queued|--shipped|--area X|--older-than DAYS]` prints one line per lesson: `#id date area status rule[:100]`. `swarm run` adds a warning `lesson-queue: N queued, oldest #id (D days)` when N > 0.
3. `lesson manifest <id> --agent A --model M [--tier cheap|mid|expensive]` prints a manifest JSON: one job `lesson-<id>`, prompt = the row's fix + evidence + the sentence "Add a node:test case in tests/field-lesson-<id>.test.mjs that fails without the fix; fixtures use fake ids, no names, repos, URLs or prompt text." Context = the files the fix names (any token matching tools/*.mjs or tests/*.mjs that exists) plus package.json; outputs = those tool files + tests/field-lesson-<id>.test.mjs. The emitted manifest must pass `swarm validate`. `lesson set <id> --status queued|built|shipped|dropped [--version V] [--test PATH]` updates the row.
4. `lesson check [--stale-days 7] [--installed DIR]` reports: shipped rows whose `test` path is missing under the installed version tree (default ~/.project-swarm/current) as `lesson-test-missing`, and queued rows older than the limit as `lesson-stale`; exit 0 with a JSON summary, non-zero only on bad input.
5. `lesson publish --version V [--file docs/lessons.md]` appends, for every row with status shipped and version V, one public entry in the existing docs/lessons.md format, built from the template `<rule> — <generic consequence>` (the `public` field if given, else rule + fix with the scrub applied). Scrub: remove or refuse private names, run ids (digits-hex pattern), repo names and owners from .swarm-projects.json and any `<owner>/<repo>` token, URLs, @handles, absolute home paths, ticket ids like T\d+, people's first names listed in the private names file. If anything survives that the check flags, refuse `public-line-unsafe` naming only the field and the pattern class, never the text. Braden approves the template once and spot-checks per release.
6. `lesson import [--from coordination/swarm-lessons.md]` converts the legacy markdown table once into the jsonl (id, date, what-happened → evidence/rule split by the first "Rule:" or "Fix:" marker when present, status parsed from `Status: …`), skipping rows already present; idempotent.
7. SKILL.md: the "Field lessons and prompt guidance" section becomes ≤10 lines: the loop in two sentences and the six commands with one clause each. Keep everything else in SKILL.md. references/lessons.md stays as the generated archive (publish may also update it if it is the same file as docs/lessons.md in this repo — check). README gets one paragraph; CHANGELOG `## 1.41.0` entry in the file's style; package.json version 1.41.0.

Rules: node:test files, shape of tests/field-lessons-batch-y.test.mjs, loading through tests/_isolate-config.mjs; fixtures with fake ids (run-0000, lesson ids 9001+), no real names, repos, URLs or prompt text. No new npm dependency. Keep every existing flag and output working; update usage/--help for every new command; no reformatting of untouched code. Mutants to name in §4: (a) `add` skips the private-names check → test fails; (b) `add --area` ignores the cap → fails; (c) `publish` lets a run id or URL through → fails; (d) `manifest` emits outputs without the test file → the validate-shaped test fails; (e) id does not continue from the legacy table → fails.
