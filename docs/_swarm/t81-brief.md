# T81 brief — speed pipeline, project-swarm 1.42.0 (decision #341)

Measured on 2026-10-01 (agent-core PR, two-tier CI): wall 18.4 min = Codex build 4 min + orchestrator hand checks 3 min + ship local checks 6 s + 10.8 min waiting for CI jobs that are not required for merge; every stage (run, inspect, integrate, checks, PR payload, ship, branch-protection repoint) was a separate orchestrator turn. Three of six Codex launches died in under 31 s with "Missing output" and the 11–16 KB of stderr discarded (state.json keeps only stderrBytes); the cause was only visible after a hand re-run. A `ship --check` on a fresh worktree with no .venv classed "Failed to spawn: pytest" as `pre-existing` and held.

Build, in order of payoff:
1. `ship --wait-required-only`: fetch the base branch's required contexts via `gh api repos/<owner>/<repo>/branches/<base>/protection/required_status_checks` (fallback: if 404/no protection, behave as today); poll only those check names; merge when all are green; output JSON gains `requiredContexts`, `pendingAtMerge` (the jobs still running), and `waitedForRequiredOnly: true`. Default stays the current behaviour.
2. `swarm ticket <manifest> --pr <payload> [--check '<json argv>']… [--repo O/R] [--branch B] [--commit-message M] [--require-section S] [--resume <run-id>]`: stages run → inspect → integrate → checks → commit (git add of declared outputs + lockfiles the checks changed; message = payload title unless given) → ship; each stage appends `{stage, status, startedAt, finishedAt, detail}` to `.swarm/runs/<id>/pipeline.json`; the first red stops with `{"status":"error","stage":…,"detail":…}` and a non-zero exit; `--resume` re-reads pipeline.json and skips stages marked ok; the final JSON carries the ship result. Reuse the existing functions; do not duplicate ship or integrate logic.
3. Workspace environment for codex (and claude-shell) jobs: if the root has `.venv/` or `node_modules/`, create a symlink in the copied workspace to the root's directory and add read + exec (never write) grants for its realpath to the sandbox profile; `run --sync` instead runs `uv sync --locked` (pyproject.toml present) or `npm ci` (package-lock.json present) inside the workspace before the job starts; the worker message gains a line listing the manifest `checks` to run before returning ("run these; fix red before you return; report `checksRun`"). In ship/integrate check classification: exit code 127, or exit 2 with `Failed to spawn`, `command not found` or `No such file or directory` in the first three lines → `check-env-missing` with hint "run uv sync --locked / npm ci in this worktree or pass --sync"; never `pre-existing`.
4. Adapter evidence: codex-adapter and claude-shell write the child's full stderr and stdout to `.swarm/runs/<id>/<job>/stderr.txt` and `stdout.txt` (streaming append, so a killed job still leaves them); `inspect <run>` prints `stderrTail` (last 20 lines) for any job whose status is not complete; `run` retries a codex job once when the job ended with no declared output written and stderr matches `/workspace routing discovery failed|Reconnecting\.\.\. 5\/5|Connection failed: error sending request/`, recording `retries: 1` and `retryReason` in state.json; a second failure is final.
5. Scaffolds: `swarm scaffold job --id X --agent A --model M --tier T --context a,b --outputs c,d [--prompt-file F] [--ticket docs/TICKETS.md#T81] [--out .swarm-manifests/X.json]` writes a manifest with timeoutMs by tier (cheap 900000, mid 1800000, expensive 2400000), `ignoreTests` filled by running the existing context check and listing the uncovered tests with the standard reason sentence appended to the prompt, and the "Return JSON only" result-shape line with status/filesChanged/reproTest; the output passes `validate`. `swarm scaffold pr --from <run-id> --title T [--repo O/R] [--out F]` writes the PR payload: `## What` bullets from each job's result (filesChanged, findings) and the CHANGELOG top entry if the run changed CHANGELOG.md, `## Checks` with the `<!-- swarm:checks -->` placeholder, `## Mutation check` with the literal stub `<!-- swarm:stub mutation -->`, the trailer lines the project uses. `ship --require-section S` refuses `{"code":"stub-section","section":S}` while the stub marker is present.
6. Release: package.json 1.42.0, CHANGELOG `## 1.42.0`, README one paragraph on `swarm ticket`, the SKILL.md "Workflow" section mentions `swarm ticket` and `scaffold` in two lines (no other SKILL.md growth).

Rules: node:test files in the shape of tests/field-lessons-batch-y.test.mjs via tests/_isolate-config.mjs; fakes for gh, git, codex and the clock (no network, no real repos); fixtures with fake ids (run-0000, 9001+), no names, repos, URLs or prompt text; no new npm dependency; keep every existing flag and output; usage text updated for every new command and flag; no reformatting of untouched code. §4 mutants (each named with the one-line change that makes the test fail): (a) wait-required-only waits on all contexts; (b) the pipeline continues past a red stage; (c) resume re-runs a green stage; (d) spawn failure classed pre-existing; (e) no stderr.txt after a failed fake codex; (f) retry fires without the blip signature or without checking for outputs; (g) scaffold pr omits the stub or ship accepts the stub; (h) scaffold job omits ignoreTests for an uncovered test. Cross-job names: T80's §3 names in docs/_swarm/t80-contract.md are fixed and already landing on this branch (tools/lessons.mjs, tools/lessons-publish.mjs, the `run` lesson-queue warning); do not rename or duplicate them.
