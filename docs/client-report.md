# Client progress reports

Phase 19, part D1 ([design](plans/phase19-design.md)). **Files only: nothing is sent**, no email, no upload. You read it, approve it, and send it yourself.

- `swarm report --client [--since DAYS] [--preview HTTPS_URL]` writes a **draft** to `.swarm/reports/client-DATE/`: `report.html` (one self-contained page, no scripts, no outside loads), `report.txt` (the same, for an email body) and `report.json` (the record). `--since` is the "this week" window (default 7 days).
- **What it shows:** the percent complete (features done of all features), each stage's progress, **done this week**, **in progress**, **coming up next** (up to 5, earliest stage first), **decisions we need from you**, and a preview link if you pass one (https only, no query string).
- **Where it comes from:** the **requirements** of the approved scope (your own sentences) and the stage names, plus ticket progress. Never from ticket titles, notes, models, costs or code. A feature counts as done when all its tickets are done (and, in a wired ledger, its integration ticket is). "Done this week" uses when the tickets reached done, read from the ticket log; a feature with no time in the log counts as done earlier.
- **Decisions for the client** are the `- ...` lines of a scope section titled `## Client decisions` (also `## Decisions needed` or `## Decisions from the client`). Nothing else becomes a decision.
- **The scan:** before the draft is written (and again when you approve it) the text is checked, and the report is refused, with what was found, if it holds: a money amount or the swarm's own spending words, a model or vendor name (Claude, Haiku, GPT, Codex, Cursor, ...), a ticket, error or run id, a file path or extension, code, an internal word (swarm, worker, agent, lane, ticket, prompt, ...), a secret-looking value, an email address, or a web address other than the preview link. Ordinary words like "price" or "cost" are allowed (a client's feature may be about prices). If a requirement trips the scan, reword it in the scope, or (for code or internal words only, e.g. a client feature that really is about a "support ticket") list the phrase, one `- phrase` per line, in a scope section titled `Report allow`. Money, vendors, ids, paths, secrets, emails and addresses can never be allowed. The HTML is read the way the client sees it: comments, scripts, images, other links and extra attributes are refused, and the status re-scans the files rather than trusting the record.
- **Approval:** `swarm report --client --approve [client-DATE]` records a hash of the files **as they are now** (you may have touched them up). `swarm report --client --status` shows each report as `draft`, `approved` or `edited` (changed since it was built or approved: approve again). A hand edit that adds something the scan refuses cannot be approved.
- Sending (Resend, or any service) is not part of this version; it needs your decision on a key (see the design).
